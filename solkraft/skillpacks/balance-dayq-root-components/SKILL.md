# Balance DayQ Root Components

Read [the root-component contract](references/ROOT_COMPONENT_CONTRACT.md) before acting.

## Workflow

1. Inspect existing item identity, physical inventory/load, crafting jobs, loot, repair, economy, power, buildings, fire, and persistence owners.
2. Trace every requested output through `source -> identify -> deconstruct -> sort -> reclaim -> grade -> standardized stock/part -> assembly -> use -> repair/recycle`.
3. Keep material distinctions only when they change strength, mass, conduction, heat, corrosion, sealing, flexibility, precision, trust, contamination, repair, or compatibility.
4. Require at least two viable routes for every ordinary non-sovereign dependency. Keep sovereign hardware strategic and non-printable.
5. Enforce mass/yield conservation, contamination, irreversible loss, grade confidence, provenance, and explicit substitution penalties.
6. Use concise player-facing families while preserving inspectable metadata. Do not invent arbitrary rare fastener blockers or direct printer inputs from generic scrap.
7. Validate graphs, schemas, economy scenarios, transaction races, interruption, rollback, migration, and live Unreal routes.

## Ownership

This skill defines abstraction, sources, grades, yields, substitution, fairness, and validation. Existing systems retain item IDs, inventory transactions, recipes/jobs, loot spawns, repair execution, economy state, and persistence.
