# Native SolForge execution contract

These are general user-designed workflows, independent of hardware project and any MCP service. Execute with tools actually available in the current host. Read this contract once per task; subsequent nodes inherit it.

Preserve the exact requested outcome, mandatory inputs, scope, existing work, and acceptance criteria. Inspect the sources and real outputs needed to support claims. Keep facts, inferences, recommendations, and unknowns distinct. A plan, queued action, or partial check is not proof of completion.

The selection graph recommends work; it grants no authority, invokes no tools, and imposes no new approval step. Continue already authorized work. Respect user and repository checkpoints. Effects such as sending, purchasing, publishing, merging, deployment, deletion, or credential changes require the applicable action and target authorization. A graph edge or an include-all request is not that authorization.

Choose the most relevant skill directly from its description; no matcher or graph read is required. Use one primary workflow per stage and only references relevant to its inputs, output, or failure. Do not read the entire catalog. Missing inputs drive targeted discovery; use existing valid evidence rather than repeat completed stages. Follow input dependencies, and use parallel agents only when separately authorized and useful. Preserve immediate Pause/Resume/Stop controls.

Finish when the requested acceptance criteria are demonstrated or a real external blocker is explained. Revisit stages only when changes, failures, or unresolved evidence warrant it. Do not impose fixed iteration counts, endless perfection loops, automatic report packages, mandatory prompts, widget selection, capsules, leases, or MCP calls on native work.

For research-only requests, Sol Search owns source and claim evidence and does not call SolForge MCP. Engineering workflows remain general planning/verification aids and yield to any product-specific engineering contract already in scope.
