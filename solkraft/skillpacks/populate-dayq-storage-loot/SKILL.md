# Populate DayQ Storage and Loot

Read [STORAGE_STOCKING_CONTRACT.md](references/STORAGE_STOCKING_CONTRACT.md). Loot/economy own scarcity; world population owns location history; inventory owns actual contents.

## Workflow

1. Establish location function, users, collapse history, later occupation, scavenging pressure and current hazards.
2. Select storage families by purpose, physical fit, access and survival history.
3. Define stocking profiles by container capacity, compatibility, organization, owner behavior and depletion.
4. Separate fixed authored evidence/strategic items from seeded ordinary contents.
5. Define locked, hidden, displaced, damaged, looted, contaminated and abandoned states.
6. Persist opened/forced/moved containers, removed contents, disturbance and replenishment source.
7. Prevent relog, cell crossing or container cycling from rerolling contents.
8. Validate economy, plausibility, navigation, search time, two-client contention and restart.

## Completion

Deliver location storage manifest, stocking profiles, seeds, authored overrides, depletion/replenishment, economy links and evidence.
