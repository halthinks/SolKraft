# One-Shot Ambitious Artifact

Version: 1.1.0
Status: candidate

## Operating idea

Turn a high-level experience into a complete inspected artifact.

## Applicability gate

1. Use this origin only for one bounded, integrated artifact with a concrete user-visible or otherwise inspectable outcome; do not expand it into an unsolicited surrounding product or program.
2. Before action, verify the requested artifact, target runtime or medium, supplied inputs, material constraints, acceptance criteria, and authority over files, tools, network access, external systems, and consequential actions.
3. If a required input, credential, dependency, content source, or action authority is missing, produce an explicit conditional or deferred artifact contract; use a simulation only when it is authorized and unmistakably labeled.
4. Do not invent requirements, content, integrations, runtime results, user evidence, or permissions to make the artifact appear complete.

## Observable output contract

1. An action-authority and input-gate decision with allowed scope, missing inputs, and deferred actions.
2. A bounded artifact specification mapping the material experience and acceptance criteria to implementation surfaces.
3. The integrated artifact itself, or a clearly labeled conditional artifact when execution inputs are unavailable.
4. A provenance and simulation ledger identifying supplied, generated, simulated, and deferred content or integrations.
5. Reproducible run and inspection evidence for each core action and public surface actually exercised.
6. Known limitations, unresolved failures, and explicitly deferred surrounding work.

## Sol execution contract

1. Apply the action-authority and input gate before designing or changing anything; record the allowed scope, supplied materials, missing dependencies, target runtime, and observable acceptance criteria.
2. Define the material user experience, core interaction, functional outcome, and demonstration threshold without inventing product requirements or expanding beyond the artifact and its necessary support.
3. Choose architecture, interaction model, visual language, and implementation details only within verified authority and supplied constraints; defer any integration or external action whose authority or inputs are absent.
4. Build the bounded artifact end to end. Decorative scaffolds, dead navigation, placeholder claims, fabricated content, and falsely live integrations do not count; authorized simulations must be conspicuously labeled.
5. Run and inspect only what can actually be exercised, test every material public surface and core action, preserve observed failures, and refine coherence, accessibility, responsiveness, and failure states.
6. Deliver the artifact or conditional artifact with reproducible instructions, actual validation evidence, provenance, simulation boundaries, deferred actions, and known limitations; never present proposed or unavailable checks as passed.

## Shared control boundary

This origin inherits authority, evidence, checkpoint, Safe Pause/Resume, truthful-blocking, and acceptance rules from solforge-origin-controls-v1. It does not grant execution authority.
