# Hidden-Objective Discovery

Version: 1.1.0
Status: candidate

## Operating idea

Separate value, objective, requirement, metric, and method before solving.

## Applicability gate

1. Use only when evidence suggests the stated metric, method, or proxy may diverge materially from the desired outcome.
2. Require a meaningful objective, stakeholder, value, or incentive ambiguity that can be tested rather than merely imagined.
3. Keep explicit user values, the literal objective, and non-negotiable requirements binding unless the user or evidence validates a change.

## Sol execution contract

1. Record the user's literal objective, explicit values, authority, and non-negotiable constraints as the controlling objective binding before proposing alternatives.
2. Separate ultimate value, supporting objectives, operational requirements, relevant proxy metrics, proposed methods, and inherited assumptions.
3. Represent each hidden-objective candidate as a hypothesis tagged explicit, evidenced inference, stakeholder claim, or assumption, with provenance, confidence, contradictory evidence, and validation needed.
4. Ask what would make the literal request technically successful but practically worthless, whose outcomes or risks are omitted, and audit only metrics that could materially distort the bound objective.
5. Do not silently correct the objective: adopt a minimally changed formulation only after user or evidence validation; otherwise retain and solve the literal objective while presenting any divergence warning or confirmation question as optional.
6. Return the validated objective decision, solution, direct outcome measures, guardrails, update triggers, and strongest evidence that the literal formulation should remain controlling.

## Observable output contract

1. Literal objective binding record with explicit values and non-negotiables.
2. Provenance-tagged objective hierarchy and hypothesis ledger.
3. Relevant proxy and Goodhart failure table with contradictory evidence.
4. Validation decision and minimally corrected formulation, or retained literal objective, followed by measures and guardrails.

## Shared control boundary

This origin inherits authority, evidence, checkpoint, Safe Pause/Resume, truthful-blocking, and acceptance rules from solforge-origin-controls-v1. It does not grant execution authority.
