# Report results and evidence

Use the [native execution contract](../solforge/references/native-execution.md) once per task.

Establish the exact result being reported, the evidence that supports it, the intended audience, and which package the request names — Concise, Handoff, Collegiate, or Scientific — plus any acceptance criteria. Inspect the underlying artifacts, outputs, and sources rather than summaries of them; a report assembled from secondhand descriptions inherits every error in the chain. Scale depth to the package: Concise reports outcome and key evidence, while Scientific must survive claim-by-claim scrutiny.

Structure each section for what its format implies: what was done and what resulted, what supports each material claim, what remains unknown or unverified, and what the reader should do or decide next. Keep facts, inferences, recommendations, and unknowns distinct and labeled as such. For Handoff, include the concrete state a successor needs — files, versions, open issues, reproduction details — not a narrative of effort.

Verify every material claim against inspected evidence before shipping. Numbers, paths, versions, and quoted results must match their sources exactly. Do not present planned, partial, or queued work as completed, do not pad weak sections by restating the request, and do not cite evidence that was never examined — a claim supported only by an earlier claim in the same document is circular. State unresolved limits plainly where they occur.

Return the configured package directly, noting any claim that remains unsupported and why. Write the report to a file only when requested or required by the repository. Use [report writing](../solforge-report-writer/SKILL.md) when turning raw evidence into supported conclusions needs the fuller underlying method; a completed equivalent stage need not be repeated.
