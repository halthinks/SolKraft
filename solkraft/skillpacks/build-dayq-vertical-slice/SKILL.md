# DayQ Vertical Slice

Integrate complete experiences, not disconnected feature demonstrations.

Read [vertical-slice-contract.md](references/vertical-slice-contract.md), locked decisions, system sheets, and canon.

## Workflow

1. Launch the current route and select the next smallest player-visible milestone. Do not audit distant dependencies unless they block it.
2. Define the geographic route, risk gradient, resource flow, faction pressure, return paths, and milestone pacing.
3. Build thin end-to-end content first: spawn to extraction to camp to outpost to industrial capability to elite raid to bunker teaser.
4. Integrate persistence, authority, save/reconnect, death/recovery, building, AI, vehicles, and economy as each milestone appears.
5. Add only the observability needed to debug the active milestone.
6. Compile and smoke-play each routine change. Validate a time horizon when the route actually reaches it; reserve the full progression arc for integration milestones.
7. Fix blockers and dominant experience failures before adding breadth.

## Rules

- Do not substitute a scripted cinematic for playable progression.
- Do not mark a milestone complete if its required systems are mocked beyond the accepted prototype boundary.
- Preserve recovery after the first major loss; failure must matter without making continuation irrational.

## Output

Deliver the playable build first. At milestone boundaries, add the current route specification, known limitations, focused results, and next playable target. Defer full matrices, performance records, and acceptance packages until integration or release gates.
