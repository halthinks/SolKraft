# Direct DayQ Storage Universe

Treat storage as physical infrastructure, not extra inventory capacity.

Read [STORAGE_UNIVERSE_CONTRACT.md](references/STORAGE_UNIVERSE_CONTRACT.md). Inspect the existing physical-inventory skill, fast-array inventory, clothing pockets, root components, crafting, building, vehicle, economy, loot, mass-content catalog, asset factory and persistence owners.

## Workflow

1. Classify the need by portable, wearable, fixed, secure/hazard, cold/environmental, base, vehicle, drone, exo or mech storage.
2. Reuse stable families and component identities. Separate container identity from contents and dynamic state.
3. Define physical envelope, opening, usable capacity, mass/load ratings, access, closures, security, environmental protection, retention, placement and movement.
4. Link shells, frames, lids/doors, hinges/slides, latches/locks, seals, handles, straps, dividers, trays, liners, wheels/casters, feet, anchors, brackets, shelves, labels and electronic modules.
5. Link materials, recipes, repair, salvage, spawn, stocking, economy and production masters.
6. Preserve UDayQInventoryComponent for contents and transfers and UDayQPersistenceSubsystem for durable state.
7. Route families to peer storage skills and the existing mass-content/asset-factory route.
8. Validate sources, sinks, reachable progression, component compatibility and storage coverage.

## Completion

Return catalog/family/component deltas, dependency graph, production jobs, runtime adapters, migration needs, evidence gates and unresolved decisions. A catalog entry is not a production asset.
