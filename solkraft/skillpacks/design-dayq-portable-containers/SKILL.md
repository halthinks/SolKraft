# Design DayQ Portable Containers

Read [PORTABLE_CONTAINER_CONTRACT.md](references/PORTABLE_CONTAINER_CONTRACT.md). Preserve physical inventory authority and use the shared storage component taxonomy.

## Workflow

1. Define empty mass, exterior/internal dimensions, usable volume, opening geometry and carry grips.
2. Define accepted item dimensions/shapes, stacking/nesting, load rating, center of load and team/lift-aid thresholds.
3. Define lid/closure/lock/seal, access posture/time, hand occupancy and interruption.
4. Define carried, dragged, dropped, thrown, stacked, strapped and vehicle-loaded behavior.
5. Define failure: cracked shell, bent lid, broken hinge/latch/handle, torn seam, jam, spill, water/contamination ingress and crushing.
6. Define repairable components, liners/dividers/inserts, labels and faction modifications.
7. Link spawn context and plausible contents separately; a container never creates contents.
8. Route production masters and representative variants through the existing asset factory.
9. Test nesting, simultaneous access, spill commits, restart and density.

## Completion

Return family/components, physical rules, slots, states, recipes, production jobs, Unreal mapping, transactions and evidence.
