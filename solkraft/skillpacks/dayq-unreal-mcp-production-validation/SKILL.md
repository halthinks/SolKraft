# DayQ Unreal MCP Production and Validation

Read [DAYQ_UNREAL_MCP_PRODUCTION_AND_VALIDATION_SKILL.md](references/DAYQ_UNREAL_MCP_PRODUCTION_AND_VALIDATION_SKILL.md) completely before taking action. It is the authoritative work-order and evidence contract.

## Required execution

1. Verify the actual Unreal, MCP, Terminal, and EditorToolset capabilities available. Never infer a live connection from source compatibility or installed files.
2. Inspect the project, ownership boundaries, authoritative systems, schemas, migrations, tests, and current evidence before changing anything.
3. Convert the approved requirement into a bounded work order with observable acceptance criteria and explicit authority.
4. Implement using project conventions without replacing existing inventory, transaction, persistence, replication, construction, combat, or defense-grid owners.
5. For a routine change, compile and run the shortest focused PIE smoke route. Capture the command and result; do not require an evidence bundle.
6. At subsystem milestones, add focused automation and one representative runtime artifact. Validate multiplayer authority, persistence/restart, performance, and failure recovery only when the change touches them or at integration/release gates.
7. Report implemented, passed, failed, deferred, or blocked truthfully. Missing noncritical proof is `deferred`, not a reason to stop building. If Unreal 5.8 or a required live tool is unavailable, preserve upstream work and mark only that live gate blocked.

For systemic-asset factory jobs, import accepted Blender output into a versioned staging package and apply `dayq/scripts/dayq_unreal_asset_promoter.py` through Unreal MCP. Do not overwrite a loaded production StaticMesh in place. Require the job spec, promoter evidence, exact live runtime mesh path, LOD/collision/socket/material/metadata inspection, a compiled runtime binding, an observable PIE interaction, and `unreal/evidence/live-pie.png` before the Unreal-integration stage passes.
