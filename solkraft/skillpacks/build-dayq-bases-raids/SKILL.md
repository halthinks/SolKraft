# DayQ Bases and Raids

Make base building physically satisfying and strategically necessary; make raids preparation-heavy operations rather than lock-and-loot events.

Read [base-raid-contract.md](references/base-raid-contract.md), the canon, and applicable construction/raid schemas.

## Construction workflow

1. Define placement, snapping, support, terrain validation, hauling, labor, tools, power, and build phases.
2. Implement authority, permissions, concurrent work, interruption recovery, and persistence.
3. Implement material-specific damage, breach, repair, demolition, and salvage.
4. Connect utilities and workshops to resource quality, specialists, noise, heat, signatures, and failure.
5. Test controller usability, replication, recovery, and exploit resistance.

## Raid workflow

1. Require discovery, surveillance, target samples, grid mapping, logistics, and readiness.
2. Model sensors, turrets, drones, redundancy, shielding, power nodes, defenders, and alternate routes.
3. Make suppression target-specific, localized, temporary, interceptable, and failure-prone.
4. Support breach, retreat, partial success, catastrophic failure, moral choices, and rival intervention.
5. Continue through occupation, repair, upkeep, defense, access control, and political consequences.

## Output

Deliver implementation, content contracts, automated tests, multiplayer evidence, exploit analysis, and acceptance results.
