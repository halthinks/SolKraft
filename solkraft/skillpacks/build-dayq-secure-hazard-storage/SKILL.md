# Build DayQ Secure and Hazard Storage

Read [SECURE_HAZARD_CONTRACT.md](references/SECURE_HAZARD_CONTRACT.md). Use existing weapons, fire, contamination, power, medicine, food, cyber, clan-permission and persistence owners.

## Workflow

1. Classify theft, tamper, fire, moisture, temperature, contamination, electrical, pressure and segregation hazards.
2. Define container construction, closure, seal, lock/authentication, ventilation, insulation/shielding, monitoring and power dependency.
3. Define compatible/incompatible contents and separation rules.
4. Define access authorization, audit, forced entry, lockout, emergency access and failed-power behavior.
5. Define component damage, ingress, contamination spread, spoilage, cook-off/fire inputs or battery fault consequences through owning systems.
6. Keep security bounded: ordinary locks, electronic controls and PQC hardware have distinct capabilities and counterplay.
7. Validate containment, breach, two-client access races, permissions, restart, faults and representative density.

## Completion

Deliver hazard/security analysis, family/component contract, permissions, environment/power adapters, production assets and evidence.
